# 多账号并行

## 使用方法

1. 侧栏打开「账号与并行任务」，输入本地账号名称并添加。已有数据自动作为「默认账号」保留，名称可以修改。
2. 切换到新账号，登录教务系统并配置它自己的清单、学期和执行参数。添加时可以复制当前账号的清单和参数；不会复制凭据、会话、课程缓存或日志，也不会自动启动任务。
3. 可以先启动账号 A，再切换到账号 B 启动它的任务；切换不会停止 A。切换前会自动保存当前清单，保存失败时保留原工作台。
4. 也可以在「账号与并行任务」勾选多个已登录、未运行的账号，点击「检查所选账号任务」。核对每个账号的当前清单、课程和前置退课后，点击「确认并行启动」。
5. 启动结果分别显示。某个账号启动失败不会撤销其他已经启动的账号；切换到相应账号的运行记录查看详细结果。
6. 「停止某账号」只停止该账号。界面的「退出程序」需要所有账号任务都停止后才会关闭本地服务。

每个账号最多同时运行一个清单。账号之间并行执行；同一个账号内部仍按既有规则执行，最多 4 个并发余量查询，选退课提交串行。不同账号可以配置相同教学班，不会共用一次提交的结果。

## 数据位置

`HDU_DATA_DIR` 仍指定整套程序的数据根目录，默认是程序旁的 `data/`。

```text
data/
  accounts.json                 账号 ID 和本地名称
  settings.json                 默认账号的原有设置
  credentials.json              默认账号的原有凭据
  courses.json                  默认账号的原有课程缓存
  ua.json                       默认账号的原有 UA 设置
  logs/                         默认账号的原有日志
  accounts/
    account-<随机 ID>/
      settings.json
      credentials.json
      courses.json
      ua.json
      logs/
```

账号名称仅用于本地显示，不作为路径或学校身份验证结果。更名不会移动数据。重启后保留账号和文件，并分别尝试自动登录；任务不会自动恢复。主题和当前选择的账号保存在浏览器 localStorage，切换账号不改变其他浏览器窗口的选择。

配置按账号保存，写入时先生成同目录临时文件再替换目标文件。凭据仍是明文 JSON；备份完整 `data/` 才会同时包含所有账号的数据。

## 实现入口

- `server/src/accounts.rs`：持久化账号目录，给每个账号创建独立 `AppState` 和 `Storage`。
- `server/src/api/mod.rs`：中间件根据 `X-HDU-Account` 请求头选择账号，将该账号状态放入请求 Extension。未知 ID 报错；兼容旧客户端时，未提供请求头默认使用 `default`。
- `GET /api/accounts` 返回账号名称和运行/登录状态；`POST /api/accounts` 接收 `{name, copy_from?}` 创建账号；`POST /api/accounts/{id}` 接收 `{name}` 更名。
- 既有业务 API 路径保持不变，凭据、设置、缓存、快照、日志和启停操作都使用请求选中的账号。请求头是数据分区标识，不是身份认证令牌。
- `src/bridge.ts` 的 `createApi(id)` 创建绑定固定账号的客户端；`AccountContext.tsx` 提供给工作台。切换时重建工作台，旧请求不能改用新账号发送后续请求。
- `useAccounts.ts` 轮询所有账号的简要状态；`AccountsDialog.tsx` 负责账号管理、任务确认和并行启动的逐账号结果。批量启动使用各账号已保存清单的快照，不使用当前账号的清单替代它们。

登录完成前会检查请求代次。扫码取消使当前账号旧扫码请求失效；切换工作台会清理其二维码计时器，其他账号会话和任务不受影响。

## 验证与边界

本地模拟测试覆盖账号配置、凭据和日志隔离，两个账号同时发起请求且使用不同 Cookie，停止一个账号时另一个继续，以及重启与清单复制。前端测试覆盖启动前确认、部分启动失败、账号切换后的旧响应和清单复制。

上述测试不使用真实学校凭据。先退后选仍不具备原子性，结果不明仍按本次失败跳过；Ctrl+C、杀进程或系统中断不具备界面停止按钮等待在途提交的保证。
