# 杭电选课 · Course Studio

基于原 HDU-KillCourse（Go）项目协议实现的浏览器版选课工具。Rust 本地服务负责与学校教务系统通信，React 界面在浏览器中使用。源 Go 项目保留在 `../Code`。

## 这是什么

啊？你不知道这是什么吗...

**便携设计**：所有数据保存在程序目录下的 `data` 文件夹里，整个文件夹（程序 + data）拷到 U 盘或其他电脑即可继续使用，不依赖系统用户目录。

## 快速开始

1. **启动程序**：Windows 双击 `hdu-course-server.exe`（无窗口、无控制台）；macOS/Linux 在终端运行 `./hdu-course-server`。程序自动打开浏览器进入界面（默认 http://127.0.0.1:6688）。
2. **登录**：点左下角「登录账号」。首次使用选择一种方式（统一身份认证 / 教务账号 / Cookie / 钉钉扫码）填入凭证；成功后凭证会保存，**以后每次启动程序都会自动尝试登录**。
3. **准备课程资料**：课程中心点「从教务获取」（有实时进度：第 X 页 · N 门），或「导入课程」选择旧版 `course.json`（不要选含凭证的 `config.json`）。
4. **核对学期**：偏好设置里确认学年、学期，然后在课程中心把想选的课加入清单。
5. **编排任务**：在「选课任务」页给每门要选的课配上"先退的课"（同类课、时间冲突课），排序，选择执行模式。
6. **开始**：点「开始任务」，在确认弹窗里核对完整计划（先退什么、再选什么），确认后执行。
7. **退出**：侧栏最下方「退出程序」关闭本地服务（关闭服务会结束正在运行的任务）。

## 界面与功能详解

### 课程中心

- **导入课程**：选择旧版 `course.json`（≤30 MB）。同一教学班的多行安排自动合并（如两段上课时间用 `;` 连接）；同名教学班内部编号不一致会**拒绝导入**。
- **从教务获取**：登录后从学校"任务落实"接口分页拉取课程（每页 500 门，最多 200 页）。慢网下单个请求 3 分钟超时、**整体 20 分钟硬上限**；按钮实时显示 `第 X 页 · N 门`（服务器返回总数时显示 `N/总数`）。
- **搜索与筛选**：按课程名 / 教师 / 教学班编号多关键词搜索，按课程类型筛选，每页 30 条。
- **详情与加入清单**：点课程名看详情（类型、时间、教师、地点、面向班级）；点右侧 `+` 加入当前清单。

### 选课任务

- **多个清单**：顶部可新建 / 重命名 / 删除 / 切换清单；每个清单**独立保存自己的执行模式**（蹲课/单次）和任务。
- **任务结构（先退后选）**：每个任务 = **一门要选的课（可为空）+ 手动指定的"先退课程"列表**。
  - 点「+ 先退的课」从课程资料库搜索挑选要退的课（同类课、时间冲突课由你自己判断、手动配对）；
  - 红色标签可单独删除；
  - 「仅退课任务」按钮创建一个只有退课的任务（左边留空、右边只退课）；
  - **同一清单内任何教学班全局唯一**：一门课只能出现一次（无论出现在"要选"还是"要退"位置），重复添加会被拒绝；
  - ↑↓ 排序控制执行顺序。
- **执行模式**：
  - **蹲课**：只允许纯选课任务（不允许带退课/仅退课），有余量时提交选课；
  - **单次**：支持先退后选配对，按清单顺序逐个执行。
- **时间参数**（蹲课模式才显示）：
  - **查询间隔**：数值 + 单位（毫秒/秒/分钟/小时），范围 100 毫秒～24 小时；
  - **波动范围**：间隔在 ±范围 内随机抖动（模拟人手点），0 关闭，上限 1 小时；**波动种子**（MT19937）可填写，默认 1919810，同一种子序列固定；
  - **开始时间**：日期时间选择器，精确到毫秒（UTC+8），留空立即开始；
  - **提前重新登录（秒）**：计划开始前 N 秒按你的登录顺序自动重连教务系统（0 关闭，上限 86400 秒；仅设置开始时间时生效）。

### 运行记录

查询、提交与异常实时显示（保留最近 1,000 条，新任务开始时清空）。状态分为：等待中 / 查询中 / 提交中 / 学校返回成功 / 学校拒绝 / 结果待核实 / 异常。

### 偏好设置

- **学期与执行偏好**：学年、学期、蹲课查询间隔与波动、外观主题（跟随系统 / 浅色 / 深色）。
- **登录顺序与凭证**：四种登录方式可 ↑↓ 排序；连接时按此顺序依次尝试。凭证（账号密码 / Cookie）**明文保存在 `data/credentials.json`**，可一键清除。请勿在共用电脑上保存密码。
- **User-Agent**（防脚本检测）：
  - **使用当前浏览器 UA**（默认）：直接采用你正在用的浏览器的 UA；
  - **固定 UA**：三个选择框拼装——操作系统（Windows/macOS/Linux）× 浏览器（Chrome/Edge/Firefox/Opera/Safari）× 版本号（每个浏览器有自己的版本列表；**Safari 只在 macOS 时可选**）；下方实时显示拼出的完整 UA；
  - **多 UA 轮换**：文本框每行一个 UA（最多 50 条），每次登录随机取一个，会话内保持不变；
  - **随机生成（MT19937）**：可填种子（默认 114514），每次登录取序列里下一个真实格式的浏览器 UA，会话内保持不变。
  - UA 在登录及之后**每个请求**使用，且同一会话内固定（像真人浏览器）；修改后建议重新登录。

### 登录弹窗

四种方式卡片按你排的顺序显示，选择后自动填出已保存的凭证。「按偏好顺序自动尝试」会依次尝试、失败换下一种；轮到钉钉扫码时弹出二维码（可「跳过此方式」）。

## 执行语义（重要细节）

1. **先退后选，逐项执行**：任务按清单顺序逐个处理——第 1 项的退课全部退完 → 第 1 项选课 → 第 2 项退课 → 第 2 项选课……不是"全退完再全选"。
2. **退课被学校拒绝** → 记录原因，**跳过该任务的选课**，继续下一个任务。
3. **退课/选课结果不明** → **暂停整轮**，提示先到教务系统核实，不盲目重试。
4. **选课被拒** → 记录原因，继续下一个任务。
5. **蹲课**：每轮最多 4 个并发余量查询；提交严格串行；学校拒绝会结束该课程本轮任务。
6. **停止任务**：取消未发出的查询与等待，不再安排新提交；**已发出的提交会等待学校回复并记录**，不声称能撤回。
7. **启动自动登录**：每次启动程序后台按保存的凭证与顺序自动登录（钉钉扫码需交互、自动跳过）；成功后打开浏览器即已连接，失败在控制台提示、仍可手动登录。
8. **提前重新登录**：定时任务在开始前 N 秒按序重登；成功换新会话，失败记录原因并沿用旧会话。
9. **浏览器标签页关闭不影响任务**：任务由本地服务继续执行，重新打开页面即可看到进度；**关闭服务会结束任务**。
10. 确认弹窗会完整展示最终计划："先退：A、B → 选：C"，请核对后再开始。

## 数据与便携性

- 数据目录：程序所在目录下的 `data/`：
  - `settings.json` — 学年学期、清单、时间参数、主题；
  - `courses.json` — 课程资料缓存；
  - `credentials.json` — 登录凭证（**明文**）；
  - `ua.json` — User-Agent 配置。
- 首次启动新版本会自动把旧版（系统应用数据目录）中的数据迁移到 `data/`（已存在的不覆盖）。
- 环境变量：`HDU_DATA_DIR`（覆盖数据目录）、`HDU_PORT`（默认 6688，也可用第一个命令行参数）、`HDU_NO_OPEN=1`（启动时不自动打开浏览器）。
- 安全提醒：服务只监听 127.0.0.1；凭证明文保存在 data 文件夹中，请勿在共用电脑或会被分享的文件夹里使用。

## 常见问题

- **"从教务获取"转很久？** 慢网下课程分页下载可能持续较久。单页请求 3 分钟超时、整体 20 分钟上限；按钮上有"第 X 页 · N 门"的实时进度。超过 20 分钟会明确报错并停止。如果下载不下来，可以使用原版HDU-KillCourse下载`course.json`并导入
- **单次模式为什么没有查询间隔选项？** 间隔/波动只在蹲课模式有意义（控制余量查询节奏），单次模式按清单逐个提交、不等待。
- **重启后要重新登录吗？** 不需要手动操作——程序启动会按你保存的凭证自动尝试登录；成功侧栏即显示"教务会话已连接"。
- **任务清单会丢吗？** 清单保存在磁盘（`data/settings.json`）。注意：清单改动后要点「保存清单」（或开始任务时自动保存）；正在运行的任务状态与运行记录只在内存，服务关闭后不保留。
- **为什么提示"请先登录"？** 自动登录未成功（无凭证 / 网络慢 / 密码变更）。手动打开登录弹窗连接一次即可。

## 开发与构建

需要 Node.js 与 Rust（Windows 另需 MSVC C++ 工具链；无 WebView 依赖）。

```sh
npm ci

# 开发：一个终端起界面（vite 把 /api 代理到 127.0.0.1:6688）
npm run dev
# 另一个终端起本地服务（开发时建议 HDU_NO_OPEN=1）
npm run server:dev

# 生成内嵌界面的正式程序（server/target/release/hdu-course-server）
npm run desktop:build
```

测试：

```sh
npm run build        # 前端构建
npm test             # 前端测试
npm run server:test  # Rust 测试
```

已验证：前端构建与 5 项测试、Rust 27 项测试全部通过（覆盖课程导入/合并/检索、多清单与时间/波动参数校验、配对任务与重复校验、旧数据迁移、登录顺序与凭证映射、MT19937 已知向量与 UA 生成、固定 UA 组装、抖动范围、AES 已知向量、学校拒绝/未知响应分类、接口端点与静态资源回退）；服务启动、健康检查、快照、设置读写、课程导入与优雅退出做过端到端验证。**未进行真实学校会话联调，未提交真实选退课。**

## 当前限制

- 尚未进行真实学校会话联调；接口协议来自本地 Go 源码，不能保证学校服务未变化。
- "学校返回成功"仅按接口明确响应判定，尚未独立查询已选课表二次核验。
- 不做自动冲突检测：先退的课由你手动指定配对；不处理学分上限（36/40）与跨年级限制（学校会直接拒绝，结果会如实记录）。
- 暂不提供验证码交互、蹲课途中登录过期自动重登、SMTP 邮件、Excel 导出、跨年级选课、重修课提交。
- 任务未做断点恢复：关闭服务或系统中断后，应先核实真实已选记录再重新开始。
- 仅构建验证 Windows x64 与 macOS Apple Silicon；Linux 与其他架构尚未验证。
